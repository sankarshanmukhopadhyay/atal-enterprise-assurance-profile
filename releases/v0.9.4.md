# v0.9.4 — v1.0 Readiness Evidence

## Release outcome

v0.9.4 makes v1.0 readiness a deterministic, machine-verifiable repository property with explicit blockers rather than an informal maintainer judgment.

## Added

- `assurance/stable-contracts.yaml` — candidate-stable schema, identifier, claim-state, and test-result contract declaration.
- `scripts/check_contract_compatibility.py` — compatibility checks over the declared stable surface.
- positive and negative core artifact fixtures under `tests/fixtures/conformance/`.
- `scripts/validate_conformance_corpus.py` — expected accept/reject corpus validation.
- `assurance/v1-readiness-criteria.yaml` — blocking readiness criteria.
- `scripts/build_v1_readiness_report.py` — deterministic JSON and Markdown readiness reports.
- `docs/v1-readiness.md` — readiness and authority-boundary guidance.

## Changed

- the canonical quality gate validates candidate-stable compatibility, the conformance corpus, and builds the v1.0 readiness report.

## Assurance impact

The repository can no longer represent itself as ready for a v1.0 decision while a declared blocking readiness criterion remains unresolved. Positive and negative fixtures also protect the intended acceptance/rejection behavior of core artifact classes.

## Expected readiness state

v0.9.4 intentionally reports `not_ready` because `V1-RDY-008` — the final governance and compatibility freeze — is pending v0.9.5. This is an expected readiness blocker, not a failed release.

## Validation

```bash
python scripts/check_contract_compatibility.py
python scripts/validate_conformance_corpus.py
python scripts/run_quality_gate.py --mode all
cat artifacts/v1-readiness-report.json
```

## Release evidence

A publishable v0.9.4 commit must pass the canonical quality gate, preserve the declared candidate-stable contract surface, produce correct positive/negative conformance behavior, and generate a readiness report that fails closed on unresolved blockers.

## Authority boundary

Readiness means readiness to enter the separate v1.0 decision gate. It is not automatic major-version promotion, deployment certification, risk acceptance, legal compliance, or regulator approval.
