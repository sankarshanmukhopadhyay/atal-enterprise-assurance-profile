# v0.9.0 — Assurance Candidate

## Release outcome

v0.9.0 consolidates the provenance, claim, evidence-strength, executable-test, and interoperability work into an adversarially checkable assurance candidate.

## Added

- `assurance/invariants.yaml` — cross-artifact invariants that define what must remain true as the profile evolves.
- `scripts/check_assurance_invariants.py` — fail-closed checks for provenance, mapping resolution, executable-test bindings, claim expiry/revocation semantics, evidence-strength progression, and quality-gate coverage.
- `.github/workflows/publish-release.yml` — governed tag and GitHub Release publication from the canonical release ledger.
- `scripts/release_governance.py` — version-contract, release-ledger, commit-target, and publication-precondition validation.

## Changed

- `scripts/run_quality_gate.py` now executes provenance, release-governance, test-catalog, external-mapping, evidence-strength, and assurance-invariant checks as part of canonical validation.
- `README.md` presents EAP as an executable assurance system rather than only a self-validating toolkit.
- `upstream/atal-baseline.yaml` now declares the repository-level v0.9.0 assurance candidate while preserving the exact ATAL v0.9 commit pin.

## Candidate posture

v0.9.0 is suitable for adversarial review and implementation trials. It is not a certification scheme. Stabilization toward v1.0 requires broader executable test coverage, worked EAP-L2/EAP-L3 deployments, external review of claim semantics, and evidence that independent implementers can reproduce assessment outcomes.

## Validation

```bash
python scripts/run_quality_gate.py --mode validate
python scripts/check_assurance_invariants.py
python scripts/release_governance.py validate-current
```

## Release evidence

A valid v0.9.0 candidate must produce a passing canonical quality gate, preserve the exact upstream ATAL baseline in `upstream/atal-baseline.yaml`, and satisfy the repository release-version contract. Publication is bound to an immutable `v0.9.0` tag at the exact validated commit, with this file used as the GitHub Release body.
