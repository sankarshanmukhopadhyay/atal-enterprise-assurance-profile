# v0.9.5 — Governance Freeze

## Release outcome

v0.9.5 completes the planned pre-v1 hardening train by resolving the final v0.9.4 readiness blocker and freezing the release-governance, authority, compatibility, and assurance-lifecycle surfaces required for a separate explicit v1.0 decision.

## Added

- `assurance/governance-freeze.yaml` — machine-readable final pre-v1 governance freeze and V1-RDY-008 blocker disposition.
- `scripts/check_governance_freeze.py` — executable verification of frozen surfaces, evidence references, immutable release safeguards, and explicit v1-decision authority.
- `docs/v1-migration-and-freeze.md` — migration expectations and v1 decision inputs.

## Changed

- `assurance/stable-contracts.yaml` advances from candidate-stable to `frozen-for-v1-decision` without changing the declared contract members.
- `GOVERNANCE.md` explicitly separates readiness evidence from v1 release authority and binds the decision to issue #12.
- `COMPATIBILITY.md` documents the frozen pre-v1 surface and explicit breaking-change disposition rule.
- the canonical quality gate validates the governance freeze before generating the readiness report.
- project, upstream, README, and changelog version surfaces advance to v0.9.5.

## Assurance impact

The repository can now distinguish three states cleanly:

1. a quality-gated assurance candidate;
2. a repository that is machine-verifiably `ready_for_v1_decision`;
3. an actually published v1.0 release.

v0.9.5 is state 2, not state 3. Major-version promotion remains a separate governance act.

## Validation

```bash
python scripts/check_governance_freeze.py
python scripts/check_contract_compatibility.py
python scripts/validate_conformance_corpus.py
python scripts/run_quality_gate.py --mode all
cat artifacts/v1-readiness-report.json
```

A valid v0.9.5 candidate MUST produce `ready_for_v1_decision` with zero blocking findings.

## Release evidence

A publishable v0.9.5 commit must pass strict release governance, preserve the exact upstream ATAL baseline, retain the frozen contract surface, verify L1/L2/L3 and adversarial assurance paths, independently verify the digest-addressed handoff, reject its tamper fixture, pass the core conformance corpus, validate the governance freeze, and generate a zero-blocker v1 readiness report.

## Remaining non-blocking limitations

- reference deployments and evidence are synthetic and do not certify a live deployment;
- regulatory approval and legal-compliance equivalence are not asserted;
- enterprise risk acceptance remains with the declared risk-acceptance authority;
- the offline quality gate does not live-query whether the pinned upstream commit remains the upstream branch tip.

## Authority boundary

`ready_for_v1_decision` does not authorize v1.0 publication. Issue #12 and a dedicated release PR remain required. No automation may infer a major-version transition from readiness status alone.
