# v0.9.2 — L3 Adversarial Assurance

## Release outcome

v0.9.2 adds a complete EAP-L3 worked assurance case and expands executable conformance testing from positive-path validation into adversarial failure detection.

## Added

- `examples/eap-l3-worked-example/` — synthetic high-impact production deployment with safety and critical-operations characteristics that deterministically require EAP-L3.
- Complete EAP-L3 evidence and assessment artifacts covering all 20 mandatory controls.
- Positive executable results for evidence-integrity, replay, reconstruction, non-bypassability, kill-switch, dual-control, and delegation-boundary vectors.
- Negative fixtures proving that undetected evidence tampering and single-approver execution are represented as failing outcomes.
- New executable vectors: `EAP-TEST-EI-001`, `EAP-TEST-RP-001`, `EAP-TEST-RC-001`, `EAP-TEST-DC-001`, and `EAP-TEST-DB-001`.
- `scripts/validate_l3_worked_example.py` — fail-closed cross-artifact validation including E4+ executable-evidence requirements for designated critical L3 controls.
- `scripts/build_l3_assurance_claim.py` — deterministic digest-bound L3 claim generation.

## Changed

- The canonical quality gate now validates mandatory L3 control coverage, adversarial fixtures, executable test bindings, critical-control evidence grade, L3 report generation, and L3 claim construction.

## Assurance impact

A conformant reference L3 assessment can no longer rely only on documentary evidence for critical enforcement, reconstruction, replay, evidence-integrity, authority-separation, and dual-control properties. The repository now demonstrates both acceptance of valid evidence and rejection of deliberately unsafe outcomes.

## Validation

```bash
python scripts/validate_l3_worked_example.py
python scripts/check_required_controls.py --level EAP-L3 --bundle examples/eap-l3-worked-example/evidence-bundle.json
python scripts/check_required_controls.py --level EAP-L3 --result examples/eap-l3-worked-example/assessment-result.json
python scripts/run_quality_gate.py --mode all
```

## Release evidence

A publishable v0.9.2 commit must pass the canonical quality gate, preserve the exact upstream ATAL baseline, contain all positive and negative L3 fixtures, and generate `artifacts/eap-l3-assurance-claim.json` plus the L3 assessment report from the checked-in source evidence.

## Authority boundary

The EAP-L3 case is synthetic reference assurance evidence. It does not certify a live system, confer regulatory approval, accept enterprise risk, or establish third-party assurance.
