# v0.9.1 — L2 Worked Assurance

## Release outcome

v0.9.1 adds the first complete EAP-L2 worked assurance case and makes that case part of the canonical repository quality gate.

## Added

- `examples/eap-l2-worked-example/deployment-profile.json` — controlled-autonomy production deployment that deterministically derives EAP-L2.
- `examples/eap-l2-worked-example/evidence-bundle.json` — evidence coverage for the complete 20-control catalog, including all mandatory L2 controls.
- `examples/eap-l2-worked-example/assessment-result.json` — conformant L2 assessment result.
- executable worked results for `EAP-TEST-NB-001` and `EAP-TEST-KS-001`.
- `scripts/validate_l2_worked_example.py` — cross-artifact validation of the complete L2 case.
- `scripts/build_l2_assurance_claim.py` — deterministic generation of a digest-bound L2 assurance claim.

## Changed

- the canonical quality gate now validates mandatory EAP-L2 evidence/assessment coverage and executable test bindings.
- the build path now generates an L2 assessment report and assurance claim.
- README and `PROJECT-STATUS.yaml` now identify the L2 worked case as repository evidence.

## Assurance impact

v0.9.1 demonstrates that EAP-L2 is not only an overlay or checklist. A declared controlled-autonomy deployment can be routed to L2, evidenced, tested, assessed, and represented by a bounded claim whose source evidence and assessment are cryptographically bound by digest.

The worked case is synthetic reference evidence. It does not certify a live enterprise deployment.

## Validation

```bash
python scripts/validate_l2_worked_example.py
python scripts/check_required_controls.py --level EAP-L2 --bundle examples/eap-l2-worked-example/evidence-bundle.json
python scripts/check_required_controls.py --level EAP-L2 --result examples/eap-l2-worked-example/assessment-result.json
python scripts/run_quality_gate.py --mode all
```

## Release evidence

A valid v0.9.1 release must:

- preserve the exact ATAL upstream baseline in `upstream/atal-baseline.yaml`;
- pass the complete canonical quality gate;
- contain all mandatory L2 controls in both evidence and assessment;
- resolve executable test results to known test and control identifiers;
- generate `artifacts/eap-l2-assurance-claim.json` from the checked-in L2 evidence and assessment;
- retain explicit separation between profile, system, assessment, and risk-acceptance authority.
